# Campus 3D — prototype

**Optional playable prototype.** The original Streamlit app remains unchanged. The playable mode reuses `game.py`, `logic.py` and `story.py`; it stores its demo progress separately.

A 3D night-time campus by the sea, drawn with Three.js. You choose a language, read the case file and walk with the arrow keys (or WASD) from the beach into the building and through the five rooms. Each room shows its title and the first text of its scene from `story.py`.

## Play the mystery (new)

From the project root:

```sh
uv sync
uv run python prototypes/campus-3d/server3d.py
```

Open **http://127.0.0.1:8765**. Keep the terminal open; Ctrl+C stops the server.
Choose a language and enter a name. The same name resumes the saved language, room,
items and decisions. Use the investigation buttons for objects/dialogue and travel
buttons to change rooms. WASD/arrows explore **within the current room**; travelling
always obeys the Python rules. The notebook contains only discovered evidence.
New game asks for confirmation, and an ending stops ordinary actions.

Prototype saves live in `data/campus3d.db`, separate from the Streamlit saves in
`data/plot_twist.db`. Optional arguments: `--port 8766 --database /path/to/demo.db`.
Names identify saves, as in the base game; they are not passwords or accounts.

**Limits:** this standard-library server is for local demos, bound to localhost.
Do not expose it as a public service. Public deployment and how to connect this
interface to the final course app still need a team decision. The 3D scenery needs
WebGL and the existing Three.js CDN. If it cannot load, the screen automatically
switches to text mode and the full mystery remains playable. No paid services.

## Run it

From the project folder:

```
uv run python prototypes/campus-3d/page3d.py
```

Then open `prototypes/campus-3d/campus3d.html` in the browser (double-click it). It needs internet: Three.js and the fonts are downloaded from a CDN.

## Files

| File | Job |
|---|---|
| `game3d.html` | The 3D page: HTML, CSS and JavaScript (Three.js). `__DATA__` is a placeholder for the texts and pictures. |
| `page3d.py` | Reads the texts from `story.py` and the pictures from `assets/`, puts them in place of `__DATA__` and writes `campus3d.html`. |
| `campus3d.html` | Generated by `page3d.py`; not in git. |

## New files

- `campus_game.py`: validates commands, calls the existing game and prepares the current scene/notebook.
- `campus_text.py`: Portuguese/English interface labels only.
- `server3d.py`: local HTTP entry point; serves only the screen files and JSON commands.
- `play.js`: buttons, render current state, confirmation and network feedback.
- `play.css`: responsive investigation panel and accessible text fallback.

The generated static HTML above is still a visual walkthrough, not the saved game.
Use `server3d.py` for the playable version.
